# 技术方案与评审结论

## 1. 技术选型
| 层 | 选型 | 理由 |
|----|------|------|
| 前端 | Vue3 + Vite + vue-router + Vant4 | H5 移动端组件齐全（日期、选择器、搜索），开发快 |
| 后端 | Go 1.26 + Gin + GORM | 单二进制部署，自动迁移建表 |
| 数据库 | MySQL 8 @127.0.0.1（root/199361） | 用户指定，库名 `lineng` |
| Excel | excelize/v2 | 生成结算单/考勤表 xlsx |
| 拼音 | mozillazg/go-pinyin | 全拼+首字母，选人搜索 |
| 鉴权 | JWT (HS256, 7天) + bcrypt | 单管理员账号，启动时自动种子 admin/admin123 |

## 2. 服务端口
- 后端 `:8080`（API 前缀 `/api`）
- 前端 vite dev `:5173`，`/api` 代理到 8080

## 3. 数据模型（GORM 自动迁移；完整 DDL 见 `backend/schema.sql`）
规范化：不存 JSON / TEXT，一个业务模块一张表。

- `users`：username 唯一、bcrypt 密码
- `projects`：no(编号 LN-YYYYMMDD-XXX 唯一)、unit、activity_name、location、party_a_owner、party_a_phone、start_date、end_date（DATE）
- `project_prices`：与项目 1:1，labor/meal/water/fork3/fork5/fork7/crane/rescue 单价（DECIMAL）+ tax_rate（百分比，6 表示 6%）
- `workers`：name(唯一)、phone、job_type、note、pinyin_full、pinyin_initial、active
- `daily_reports`：project_id + report_date 唯一（一天一单，重复保存=编辑）、is_outsourced、notes
- `report_workers` ①用工名单：report_id、worker_id、worker_name(快照)、start_time、end_time（TIME）、overnight、sort_order
- `report_shifts` ②用工人数：day_count / evening_count / dawn_count
- `report_meals` ③餐费：breakfast / lunch / dinner / supper / water
- `report_equipment` ④设备台班：equip_type(ENUM FORK3/FORK5/FORK7/CRANE/RESCUE) × shift_type(ENUM DAY/EVENING/DAWN)，每单固定 15 行
- `report_outsourcing` ⑤外包：unit_name、白/晚/凌人数、ot_start/ot_end（TIME，可空）、overnight、sort_order

说明：
1. 名单一次勾选多人 = 多行共享同一 start_time/end_time；名单行数即考勤工数，可直接 SQL 聚合。
2. 保存日报在一个事务内完成：主表 upsert → 名单/外包先删后插 → 人数/餐费/台班按主键 upsert。
3. 外键级联写在 `schema.sql`；GORM 不生成外键，故删除日报由接口在事务内显式清理五个子表。
4. DSN 开启 parseTime，模型用自定义类型 `Date`(YYYY-MM-DD) / `Clock`(HH:MM) 承载 DATE/TIME，避免扫成 RFC3339 字符串；GORM 的 `type:time` 会退化成 datetime(3)，故标注 `time(0)` 以落地 MySQL TIME 列。
5. 为兼容前端，`Project.Prices` 仍返回单价 JSON 字符串，但它是派生字段（`gorm:"-"`），真实数据在 `project_prices`。

## 4. API 一览（均需 Bearer Token，除 /api/login）
```
POST /api/login                     {username,password} → {token}
GET  /api/me
# 项目（列表/详情返回 prices 为派生字段，不落库）
GET/POST /api/projects              列表/创建
GET/PUT/DELETE /api/projects/:id    详情/更新/删除
# 人员
GET  /api/workers?q=                列表（q 支持汉字/全拼/首字母模糊）
POST /api/workers                   创建（后端自动算拼音字段，姓名查重）
PUT/DELETE /api/workers/:id
# 日报
GET  /api/reports?projectId=&start=&end=   按项目列出（返回每单完整明细）
GET  /api/report/:projectId/:date          取某天（无则空壳）
POST /api/report                           {projectId,reportDate,...} upsert
DELETE /api/report/:id                     删除本单及五个模块子表
# 统计
GET  /api/stats?projectId=&start=&end=  卡片+人员排行+项目汇总+明细
# 导出
GET  /api/export/settlement?projectId=&start=&end=&laborPrice=...&taxRate=  → xlsx
GET  /api/export/attendance?projectId=&month=2026-10                        → xlsx
```

## 5. 结算单导出对齐模板《本地（北京）结算单-刘冬艳.xls》
区块顺序：抬头两行 → 人工(日期×白/晚/凌) 合计×元/人 → 人工合计金额 → 餐费(早点/中餐/晚餐/夜宵/水) 合计×元/份 → 餐费合计金额 → 叉车3吨/5吨/7吨 台班明细 + 「N台×单价=金额元」算式行 → 吊车 → 救援车 → 人工餐费设备吊车救援车合计 → 税费6% → 劳务总合计金额。

## 6. 考勤表导出对齐模板《2026年4月-12月考勤表》
Sheet 名「{m}月份」；首行 `m月份 | 1..31 | 合计`；行=人员（按拼音排序）；格=该人员当日名单行数（工数）；末列合计。

## 7. 评审结论（风险与对策）
1. 一天多单 → V1 一天一单（upsert），满足考勤/结算口径。
2. 人数与名单不一致 → 保存时自动按名单行数预填班次人数，允许手改。
3. 生僻字 → pinyin 失败回退原字符；搜索同时匹配 name。
4. 导出价格参数化，项目可存默认价，导出时可覆盖。
